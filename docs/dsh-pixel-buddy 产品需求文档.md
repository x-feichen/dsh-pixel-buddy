# dsh-pixel-buddy 产品需求文档(PRD)

---

## 1. 背景与目标

### 1.1 背景

DSH Web 是面向开发者/用户的会话式交互界面。在与模型交互的过程中,用户存在等待响应、任务执行、异常处理等多个阶段,当前界面对这些状态的呈现较为功能化,缺乏情感化反馈,长时间等待或连续报错时容易让用户产生枯燥、焦虑或"系统是否卡住"的疑虑。

dsh-pixel-buddy 是一款安装于 DSH Web 端的桌面宠物插件。插件在页面固定位置常驻一个像素风格的小伙伴形象,通过监听 DSH 会话状态事件,以静止美术资产 + 轻量视觉信号的方式,向用户传达当前会话所处的状态,在不打断用户主任务流程的前提下,提升交互过程的情感温度与状态可感知性。

### 1.2 产品目标

1. 让用户无需盯着日志或界面细节,仅通过余光扫一眼右下角的小伙伴,即可判断当前会话大致处于何种状态。
2. 在长时间等待、任务完成、出现异常、需要人工介入等关键节点上,提供轻量但明确的视觉反馈,降低用户的不确定感。
3. 以极低的性能与资源开销实现上述目标,不影响 DSH Web 主体功能的性能表现。

### 1.3 本期(MVP)范围声明

本期 PRD **仅覆盖"状态感知与表情/动作系统"这一功能模块**,即:宠物形象随 DSH 会话状态变化展示对应的静态徽章与颜色信号。以下能力已在方案讨论中提出,但**明确不在本期范围内**,将在后续版本评估:

- 点击互动、拖拽、右键菜单等交互能力
- 养成/个性化系统(等级、皮肤解锁、心情值等)
- 悬浮提示卡片、后台任务完成后的"举手汇报"等主动通知能力
- 多角色皮肤

## 2. 术语定义

| 术语                  | 定义                                                       |
| --------------------- | ---------------------------------------------------------- |
| 宠物本体 / 精灵图     | 固定造型的像素风格角色主图,MVP 阶段为单张静态图,无循环动画 |
| 徽章(Badge)           | 叠加在宠物本体右上角的小尺寸状态标识,用于传达当前会话状态  |
| 状态事件(State Event) | DSH 插件 Hook API 抛出的、代表会话生命周期变化的事件       |
| 过渡(Transition)      | 状态切换时,徽章从旧状态到新状态的视觉变化过程              |
| 静止态                | 宠物本体和徽章均无持续性动画的默认展示状态                 |

## 3. 用户与使用场景

### 3.1 目标用户

DSH Web 的日常使用者,尤其是需要频繁与模型进行多轮交互、等待任务执行结果的用户。

### 3.2 核心使用场景

- 用户发起一次请求后,不需要一直盯着输出区域,通过宠物徽章即可感知"是否还在处理中"。
- 任务顺利完成时,用户能够在余光范围内获得一个明确但不打扰的"完成"信号。
- 任务失败或需要用户进一步操作(如确认、授权)时,徽章持续提示,直到用户主动处理,避免关键信息被忽略。

## 4. 功能需求

### 4.1 宠物形态与展示位置

| 项目     | 需求说明                                                                            |
| -------- | ----------------------------------------------------------------------------------- |
| 展示位置 | 页面右下角固定悬浮                                                                  |
| 尺寸     | 小尺寸展示(建议 32px~48px 区间,具体数值由视觉设计阶段确定),不干扰主界面内容         |
| 本体动画 | 无持续性动画（**修订 2026-09-06**：新增可选'待机眨眼'——每 4.6s 闭眼约 92ms，纯 CSS keyframes 零 JS 循环，设置项默认关闭，prefers-reduced-motion 时停用；性能红线不破。验收 7 相应调整为'默认状态下本体无动画'） |
| 层级     | 悬浮于页面内容之上,不遮挡关键操作区域                                               |

### 4.2 状态定义与事件映射

MVP 阶段定义 5 种会话状态,分别对应 DSH Hook API 抛出的事件。具体事件名称需在技术方案阶段与 DSH 插件 Hook API 文档对齐,下表中的事件命名为占位示意。

| 状态     | 说明                                       | 对应徽章 | 徽章颜色    | 触发条件(占位,待与 Hook API 对齐)                  |
| -------- | ------------------------------------------ | -------- | ----------- | -------------------------------------------------- |
| 待机     | 无进行中的会话活动                         | 无徽章   | 无          | 默认状态 / 上一状态结束且无新事件                  |
| 运行中   | 会话正在处理请求(如模型流式响应中)         | `•`      | 蓝色        | 例如 `stream:start` 至 `stream:end` 之间           |
| 需要人工 | 会话需要用户进行确认、输入或授权等主动操作 | `?`      | 黄色/琥珀色 | 需与产品/工程明确具体触发场景(见第 8 节待确认事项) |
| 报错     | 会话执行过程中出现异常                     | `!`      | 红色        | 例如 `error` 事件                                  |
| 成功     | 会话任务顺利完成                           | `✓`      | 绿色        | 例如 `stream:end`(正常结束)                        |

### 4.3 徽章视觉规范

- 徽章展示于宠物本体**右上角**,尺寸需与宠物本体尺寸保持视觉比例协调,不喧宾夺主。
- 徽章符号采用简洁的字符级图形(圆点、问号、叹号、勾号),不采用复杂插画,以保证在小尺寸下依然清晰可辨。
- 徽章自身携带状态色,颜色信息**收敛于徽章本身**,宠物本体不额外做描边/滤镜换色处理。
- 出于色觉可及性(color accessibility)考虑,徽章以"符号 + 颜色"双重编码传达状态,避免仅依赖颜色区分,照顾色弱/色盲用户的识别需求。

### 4.4 状态过渡规范

- 状态切换时,**宠物本体不做任何动画效果**(不弹跳、不抖动、不缩放)。
- 仅徽章本身发生变化,采用**交叉淡入淡出(crossfade)**方式过渡:
  - 旧徽章:透明度由 1 过渡至 0
  - 新徽章:透明度由 0 过渡至 1,与旧徽章同步进行
  - 建议过渡时长:100ms~150ms(具体数值由视觉/前端实现阶段验证调整)
- 待机状态与其他状态之间的切换(即"徽章消失/出现")同样遵循上述交叉淡入淡出规则。

### 4.5 状态优先级与并发处理规则

当多个状态事件在短时间内连续触发时,需按以下优先级决定当前展示的徽章,高优先级状态可打断低优先级状态的展示:

```
报错 > 需要人工 > 运行中 > 成功 > 待机
```

### 4.6 状态展示时长与消失规则

| 状态     | 消失规则                                                                      |
| -------- | ----------------------------------------------------------------------------- |
| 报错     | 持续展示,**不自动消失**,需用户主动交互(点击宠物/相关提示)后才转回待机         |
| 需要人工 | 持续展示,**不自动消失**,规则同"报错",避免关键待办信息被自动清除               |
| 运行中   | 持续展示至任务结束,自然过渡至"成功""报错"或"需要人工"                         |
| 成功     | 展示不少于设定的最短时长(建议 2~3 秒,具体数值待验证),超过后自动淡出并转回待机 |
| 待机     | 默认态,无展示时长限制                                                         |

> 说明:"报错"与"需要人工"均属于需要用户主动确认的事项,不适用自动消失机制,以避免用户错过关键信息;"成功"为非阻塞性的正向反馈,应在提示到位后尽快让出视觉焦点。

## 5. 非功能需求

| 类别       | 要求                                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 性能       | 插件不引入持续性 JS 动画循环(如 `requestAnimationFrame` 轮询);状态切换基于事件驱动 + CSS `transition` 实现,避免常态化性能与电量开销 |
| 兼容性     | 需覆盖 DSH Web 支持的主流浏览器环境(具体范围以 DSH Web 官方兼容性要求为准)                                                          |
| 可访问性   | 状态信息不得仅依赖颜色传达,需辅以符号进行冗余编码(见 4.3)                                                                           |
| 视觉一致性 | 徽章与宠物本体的美术风格需与 DSH Web 整体视觉调性协调,避免风格割裂                                                                  |
| 资源占用   | 美术资产总量控制在最小规模:1 张宠物本体精灵图 + 4 种状态徽章图形(或对应 CSS/SVG 实现),不需要多帧动画序列                            |

---

## 6. 技术依赖与约束

- 插件运行依赖 DSH 插件系统提供的**会话状态事件 Hook API**,需要能够监听至少以下类别的事件:任务开始/进行中、任务正常完成、任务异常、需要用户介入。具体事件粒度(是否支持逐 token 级别事件、是否可获取错误详情、是否支持多会话并发等)需在技术方案阶段与 DSH 插件系统文档对齐并补充到本文档的附录中。
- 若 DSH 插件系统支持多标签页/多会话并发,需在技术方案阶段明确:宠物是否仅反映"当前激活会话"状态,或需要额外的多会话状态合并/队列展示逻辑。本 PRD 暂不对此做出规定,留待技术方案补充。

## 7. 验收标准

1. 插件安装后,页面右下角展示固定尺寸的静态像素宠物,默认无徽章。
2. 会话进入"运行中"状态时,宠物右上角在 150ms 内以交叉淡入淡出方式展示蓝色圆点徽章。
3. 会话正常结束时,徽章交叉淡入淡出切换为绿色勾号,并在设定的最短展示时长后自动淡出回到无徽章状态。
4. 会话出现异常时,徽章切换为红色叹号,且在用户主动点击交互前不会自动消失。
5. 会话进入"需要人工"状态时,徽章切换为黄色问号,且在用户主动交互前不会自动消失。
6. 短时间内连续触发多个状态事件时,展示的徽章符合第 4.5 节定义的优先级规则,不出现闪烁或状态错乱。
7. 宠物本体在任意状态下均无持续性动画,仅徽章发生变化。
8. 插件运行期间,不产生持续性的 JS 动画循环或明显的额外性能开销(具体验收方式由测试阶段补充,如 CPU/内存占用对比)。

## 8. 待确认事项(Open Questions)

以下问题需在技术方案设计或下一轮需求评审中明确,当前 PRD 暂不做出结论:

1. **"需要人工"状态的具体触发场景**:目前尚未明确对应 DSH 的哪一类具体事件(例如:操作权限确认、用户输入确认、审批请求等),需要产品与工程共同定义,并可能影响是否需要在徽章旁配合简短的文案提示。
2. **DSH Hook API 的事件粒度**:是否支持逐 token 级别事件、错误信息的可读取程度、是否支持多会话并发等,需要以实际接口文档为准进行技术方案补充。
3. **过渡动效的具体时长参数**(如 100ms 或 150ms)与"成功"状态的最短展示时长,需要在视觉稿和前端联调阶段进行实际体验验证后确定最终数值。
4. **徽章与宠物本体的美术风格细节**(像素颗粒度、色值、圆点/问号/叹号/勾号的具体绘制方式),需交由视觉设计阶段输出正式美术规范。
