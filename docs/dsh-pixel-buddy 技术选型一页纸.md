## 1. 插件形态选型

| 方案                              | 样式隔离                               | 宿主侵入性                                                      | 事件接入                | 多标签页 | 结论           |
| --------------------------------- | -------------------------------------- | --------------------------------------------------------------- | ----------------------- | -------- | -------------- |
| **A. Web Component + Shadow DOM** | Shadow DOM 原生隔离，徽章样式零泄漏    | 仅挂载一个自定义元素                                            | 宿主全局 API 照常可订阅 | 无影响   | **✅ 采用**    |
| B. 直接 DOM 注入 + scoped class   | 依赖手工命名约定，宿主样式可能穿透徽章 | 分散插入多个节点                                                | 同 A                    | 同 A     | 隔离不可靠，弃 |
| C. iframe 悬浮                    | 完全隔离                               | 额外文档开销；点击事件跨 frame 处理繁琐；小尺寸下渲染成本不划算 | 需 postMessage 桥接     | 同 A     | 过重，弃       |

**结论：方案 A。** 宠物本体 + 徽章封装为单一自定义元素 `<dsh-pixel-buddy>`，Shadow DOM (`mode: 'closed'`) 隔离样式与点击热区，固定挂载于 `document.body`。这同时满足 PRD §5"视觉一致性"与"不干扰宿主"的要求，且为后续皮肤/表情版本留出组件化扩展空间。

## 2. 技术栈

| 层         | 选型                               | 理由                                                                           |
| ---------- | ---------------------------------- | ------------------------------------------------------------------------------ |
| 语言       | **TypeScript (strict)**            | 状态机与契约需要类型约束；`SessionEvent`/`BuddyState` 直接以类型即文档         |
| 构建       | **Vite**（lib mode）               | 产物为单 IIFE/ESM 文件，构建配置最小；dev server 便于联调                      |
| 运行时依赖 | **零依赖**                         | PRD §5 资源红线：不引入框架（React/Vue 都不进插件包），自绘 Web Component 足够 |
| 状态机     | 纯函数 reducer（无类状态、无框架） | 可测性最大化：`(state, event) => state`，fuzz 测试直接遍历                     |
| 单测       | **Vitest**                         | 与构建同链路；支持属性级 fuzz 与覆盖率                                         |
| 代码规范   | ESLint + Prettier + `strict: true` | —                                                                              |

## 3. 样式与渲染约束（性能红线落地）

1. **零 rAF、零常态定时器**：仅允许两类一次性 `setTimeout`——适配层去抖（200ms）、粘滞/超时降级；成功徽章淡出用一次性定时器。全部在组件卸载时清理。
2. 过渡仅用 CSS `transition`（opacity 150ms，常量 `CROSSFADE_MS`）；本体永不携带 transition/animation 属性。
3. 本体图 `image-rendering: pixelated`；徽章优先 SVG/CSS 实现（美术需求单 §6.1）。
4. 层级：宿主 body 直挂，`z-index` 交给挂载时探测（见 T1.2），组件内部不感知页面其余部分。
5. `prefers-reduced-motion: reduce` 时 crossfade 时长置 0（T2.2 可访问性，容器层一次性实现）。

## 4. 构建与本地联调

| 项       | 方案                                                                                                                                                                             |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 产物     | `dist/dsh-pixel-buddy.iife.js`（单文件，自动注册 `<dsh-pixel-buddy>`）                                                                                                           |
| 本地联调 | Vite dev 模式提供 `devhost.html` 模拟宿主页面 + 事件触发面板（可手动派发 4 类内部事件），在 DSH 真实宿主可用前充当联调载体；真实 `DshHookAdapter` 以桩实现接入，回填时零改动上层 |
| 插件卸载 | 提供 `buddy.destroy()`：解绑事件、清空定时器、移除节点（对齐核实清单 #8）                                                                                                        |
| 分发     | 按 DSH 插件分发流程（T3.1 前确认），产物形态满足"script 注入即生效"                                                                                                              |

## 5. 浏览器兼容矩阵

以 DSH Web 官方兼容要求为准（⚠️ 待 DSH 文档确认，下表为工程侧建议基线）：

| 浏览器        | 版本基线 | 依据能力                                                                    |
| ------------- | -------- | --------------------------------------------------------------------------- |
| Chrome / Edge | ≥ 88     | Web Components v1、Shadow DOM、`structuredClone` 不需要——全部特性在此基线内 |
| Firefox       | ≥ 90     | 同上                                                                        |
| Safari        | ≥ 14     | 同上                                                                        |

- 矩阵内浏览器 T2.4 全量回归；DSH 官方基线若更宽/更窄，以官方为准修订本表（核实项挂账：#9）。
